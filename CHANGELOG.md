# Changelog

## [2026-07-30]
- added: `credroute login`, a guard that sits in front of a platform's own login command so a credential write can be refused BEFORE it happens. It resolves the identity from the directory, reconciles it against `--expect` and against the destination the caller asked for, refuses on any disagreement, snapshots the slot first, runs the platform login, then confirms which identity actually landed and rolls back if it is the wrong one. This closes the gap that made the tool's own premise unmet: until now nothing could see a credential write before it occurred.
- added: `internal/slotsnap`, snapshot and confirmed-restore for credential slots. The restore re-reads from disk and refuses to report success it has not verified, including when the slot is a symlink, where copying the link instead of the credential behind it silently destroyed the original.
- added: a slot marker written before the platform login runs, so a login killed part-way leaves the slot refused rather than trusted on its previous label. Without it, an interrupted login left the wrong credential under a stale "verified" record and the next command ran as the wrong account.
- added: an exclusive per-slot lock, so two logins cannot interleave and leave one process's identity record over another's credential.
- removed: `verify --after-login`. It was parsed, validated, and never read: the spec called it the generalized login guard and the manifest advertised it, but it did nothing. It now exits with a message naming `credroute login`.
- removed: `--accept-ambient-destination` and `--accept-unverified-login`, collapsed into a single audited override. Three separate break-glass flags produced two defects between them, including one that let an audited bypass run with no audit record when the audit write failed.
- changed: verify modes are now `on` and `off`. `advisory` is migrated to `on` with a warning naming the file; every edge moved stricter, none looser.
- removed: `command_patterns`, a config field that was parsed and shipped in the google profile and read by no code, and scope-excess checking, which served no part of the tool's purpose.
- changed: a failed platform login now passes the child's exit code through, so a caller can tell a mistyped flag from a failed browser login.

## [2026-07-25]
- fixed: hardened the Claude Code hook, audit gates, scope checks, sync-conflict refusal, and exec argument boundary. The hook now checks command tokens by basename, handles common shell separators and command substitutions, and keeps URL/remote specs from matching; it remains a best-effort convenience check, not a security boundary, because name-based detection cannot be complete: a renamed copy of the binary, or variable indirection such as `X=/usr/bin/gh; $X auth token`, defeats it and is out of scope. The security boundary is the vault plus credroute's identity verification before secret handoff. Break-glass handle access fails if its audit entry cannot be written, `resolve`/`exec` refuse observed over-scoped credentials under `verify: required`, config loads refuse newer sync-conflict siblings, and child `--config` flags stay with the child command. Docs now state that audit logs are diagnostic, not tamper-proof evidence, and that `CREDROUTE_STATE_DIR` moves the audit trail.
- fixed: the hook now treats single-quoted strings as literal text except in command positions, where they are shell input: `eval '...'`, `sh|bash|zsh -c '...'`, and the command argument of `ssh host '...'` are recursed into and detected, while `echo 'gh auth token'` and `echo 'git push'` are correctly allowed as literals
- fixed: `exec` and `handle get` now fail closed when a fresh verification observes a mismatch but the attestation cannot be recorded; audit entries keep the true observed status.
- changed: attestation records are now bound to vault handle, identity, platform, and access level; `handle get` refuses unmodeled and ambiguous handles by default, with `--allow-unmodeled-handle` as an audited break-glass path.
- added: `credroute verify --accept-baseline` for fingerprint-only platforms. Plain `unconfirmed` no longer exits 0 under `verify: required`; an explicit `accepted_baseline` passes until the secret fingerprint changes.
- added: `scripts/scan-private-data.sh`, a check that refuses to publish personal paths or secret material. It runs as a pre-push hook, as a CI job, and as a gate before any release tag is cut. Install it with `scripts/scan-private-data.sh --install-hook`; see the Contributing section of the README.
- added: `scripts/private-data-baseline.txt`, the list of placeholder paths this repository is allowed to contain. Anything not on it blocks the push.
